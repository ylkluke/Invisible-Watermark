# Invisible Watermark

基于 PyTorch 的数字图像不可见水印系统，支持模型训练、单图推理、批量测试、鲁棒性评估、消融实验和 Streamlit 可视化演示。

系统以 RGB 图像作为载体，将水印模板转换到 YCbCr 空间后只编码 Y 通道。模型先将水印 Y 通道转换为噪声形式的 payload，再通过嵌入网络生成含水印图像；恢复阶段从含水印图像中提取 payload 并重建水印 Y 通道。可视化恢复结果时，会复用原水印模板的 Cb/Cr 色度通道。

## Features

- End-to-end invisible image watermarking model
- Watermark-to-noise encoding and payload recovery
- U-Net based residual embedding network
- Common image attack simulation: crop, resize, JPEG, blur, mosaic
- Robust training and attack-aware evaluation
- Plain vs robust comparison scripts
- Ablation experiment scripts
- Streamlit demo for interactive visualization

## Repository Structure

- `src/nn/edge_wm/`: model, loss functions, and attack modules
- `experiments/`: training, inference, and testing entry points
- `scripts/`: helper scripts for environment, comparison, ablation, and packaging
- `app_demo.py`: Streamlit demo application
- `assets/watermarks/`: example watermark templates
- `config.toml`: default configuration
- `requirements.txt`, `environment.yml`: runtime environment definitions

Large generated files are intentionally excluded from this repository:

- training datasets such as DIV2K
- model checkpoints such as `*.pt`
- generated outputs under `outputs/`
- packaged archives under `deliverables/`

Prepare these files locally when running training or inference.

## Training

Prepare training images under:

```text
inputs/div2k/DIV2K_train_HR/
```

Run robust training:

```bash
python experiments/edge_wm_noise_train.py \
  --input-dir inputs/div2k/DIV2K_train_HR \
  --wm-template assets/watermarks/luke.png \
  --outdir outputs/edge_wm_noise/train_run \
  --steps 2000 \
  --batch-size 4 \
  --num-workers 2 \
  --device cpu \
  --robust
```

Training outputs include checkpoints, metrics logs, summaries, and sample images under the selected `outputs/` directory.

## Inference

After training or downloading a checkpoint locally, run single-image inference:

```bash
python experiments/edge_wm_noise_infer.py \
  --input path/to/cover.jpg \
  --wm-template assets/watermarks/luke.png \
  --ckpt outputs/edge_wm_noise/train_run/ckpt_last.pt \
  --outdir outputs/edge_wm_noise_infer/demo_run \
  --device cpu
```

The output directory contains the cover image, watermarked image, residual visualization, recovered watermark, payload visualization, and `run.json`.

## Batch Test

```bash
python experiments/edge_wm_noise_test.py \
  --input-dir path/to/test_images \
  --wm-template assets/watermarks/luke.png \
  --ckpt outputs/edge_wm_noise/train_run/ckpt_last.pt \
  --outdir outputs/edge_wm_noise_test/demo_batch \
  --device cpu \
  --save-samples 8 \
  --attack --attack-mode all
```

The test script writes:

- `metrics.jsonl`: per-image metrics
- `summary.json`: aggregate metrics
- `samples/`: visual examples

## Demo

Launch the Streamlit demo after preparing a local checkpoint:

```bash
streamlit run app_demo.py
```

The demo supports image upload, checkpoint selection, watermark template selection, attack configuration, visual result comparison, and metric display. See [DEMO.md](DEMO.md) for details.

## Comparison And Ablation

Plain vs robust comparison:

```bash
bash scripts/run_compare_robust_vs_plain.sh compare_r1 800 cpu 2 0 \
  inputs/div2k/DIV2K_train_HR path/to/test_images assets/watermarks/luke.png
```

Ablation experiments:

```bash
bash scripts/run_ablation_suite.sh ablation_r1 800 cpu 2 0 \
  inputs/div2k/DIV2K_train_HR path/to/test_images assets/watermarks/luke.png
```

## Notes

- The model restores the watermark Y channel, not a full RGB watermark directly.
- Recovered RGB watermark images are visualization outputs generated by combining the recovered Y channel with the original template Cb/Cr channels.
- Checkpoints and datasets are not tracked by Git. Keep them in local `inputs/` and `outputs/` directories.
